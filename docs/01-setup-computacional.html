1  Ayudantía 1 — El kit computacional del investigador

TipObjetivo de la sesión

Salir de esta ayudantía con dos cosas: (1) un entorno de investigación completo y funcionando —R, un editor con asistente de IA agéntico, Git y Quarto—, y (2) claridad total sobre las reglas del juego del curso: cómo se usa la IA, cómo se evalúa y qué es lo que nunca se delega.

1.1 Por qué esta sesión existe

Todos ustedes ya usan IA. En este curso, lejos de prohibir su uso, la alentamos, así que debe hacerse bien. Usar la IA en una ventana de chat está, para investigadores, obsoleto. En el chat el asistente no ve tu proyecto completo: responde sobre una descripción de tu problema. Además, usando chatbox se pierde la reproducibilidad de tu trabajo.

Un asistente integrado en un IDE (Integrated Development Enviroment) trabaja distinto: lee los archivos de tu proyecto, escribe y ejecuta código ahí mismo, ve el error que produce y lo corrige. Es más parecido a un ayudante de investigación que a un mero chat. Este curso —y probablemente el resto de tu doctorado— funciona mejor con esa segunda forma de trabajo.

La contracara es que un asistente más capaz hace más fácil producir resultados que no entiendes.

1.3 Demo: qué se puede hacer con IDE + IA

Veamos un ejemplo de lo que podemos hacer con una encuesta (ficticia) en Excel.

Leeremos el archivo libro-redes-sociales-2026/datos/encuesta_nominaciones.xlsx. Tiene columnas:

  • sexo
  • edad
  • disciplina
  • nom_1 a nom_7.

Cada fila es un ego y cada nominación un vínculo dirigido.

Primer prompt (texto plano: pasa el cursor por el bloque y aparece el botón de copiar):

Lee el archivo libro-redes-sociales-2026/datos/encuesta_nominaciones.xlsx. Es una encuesta con generador de nombres: las columnas nom_1 a nom_7 contienen las personas nominadas por cada encuestado (red dirigida; las demás columnas son atributos). En R: (1) construye la matriz de adyacencia dirigida a partir de las nominaciones; (2) calcula la densidad, el grado de entrada y de salida de cada persona, y la reciprocidad/balance de la red; (3) ajusta un ERGM bien especificado con términos estructurales (edges, mutual, geométricamente ponderados tipo gwesp) y de homofilia (nodematch por disciplina y por sexo); (4) reporta e interpreta los coeficientes con cautela, indicando qué NO se puede concluir.

Segundo prompt:

Ahora escribe un reporte en formato Markdown en libro-redes-sociales-2026/outputs/reports/reporte_encuesta.md que incluya: descripción de los datos, tabla con las métricas por persona, resultados del ERGM en tabla, y una sección final con tres advertencias de interpretación.

Tercer prompt (el trabajo no existe hasta que está en el repositorio):

Haz commit del reporte y push al repositorio Redes-Sociales-2026, con un mensaje que describa lo que se creó.

Esto es, básicamente, lo que veremos en este curso — y el ciclo completo del trabajo reproducible: datos → análisis → reporte → publicado con su historial. Ahora, ¿quién entendió el ERGM?

2 Instalación IDE, extensiones, y comunicación con GitHub

2.1 1. El IDE

Lo primero es saber qué suscripción de IA tienes o tendrás — ¿Claude (Anthropic)? ¿ChatGPT/Codex (OpenAI)? ¿Google AI Pro? — porque eso define tu ruta. Si no tienes ninguna, avísame: la ruta gratuita es GitHub Copilot con el Student Developer Pack.

2.1.1 Ruta A — VS Code, para quienes usan Claude, ChatGPT/Codex o Copilot

  1. Instala VS Code.
  2. Activa tu agente según suscripción:
    • Claude: extensión Claude Code (anthropic.claude-code).
    • OpenAI: extensión Codex (openai.chatgpt).
    • GitHub Copilot: ya viene integrado en VS Code.

2.1.2 Ruta B — Antigravity, para quienes tienen Google AI Pro

Es el IDE agéntico de Google; es un derivado de VS Code, así que casi todo lo de la Ruta A aplica igual.

  1. Instala Antigravity.
  2. Inicia sesión con tu cuenta Google del plan Pro: el agente (Gemini) viene integrado.
Nota

El curso es agnóstico a la herramienta. Todo lo que haremos (leer archivos, ejecutar R, renderizar Quarto, criticar resultados) funciona igual en ambas rutas.

2.2 2. El kit que se instala desde la terminal

El IDE trae una terminal integrada para ejecutar comandos (menú Terminal → New Terminal; atajo: ⌃⇧` en macOS, Ctrl+Shift+` en Windows).

Las tres herramientas que instalaremos desde ahí, y para qué sirve cada una:

  • R — el lenguaje de análisis del curso: métricas de redes, modelos y visualizaciones.
  • Quarto — el sistema de publicación científica: un solo archivo .qmd mezcla texto y código, y al renderizarlo ejecuta el código e inserta los resultados en un HTML o PDF. El formato de tus entregas (y de este libro).
  • Git — el control de versiones: registra la historia de cambios de tu proyecto, commit a commit. La diferencia entre tesis_final_v7_AHORA_SI.R y un historial ordenado al que siempre puedes volver.

(RStudio es opcional; el flujo principal del curso es el IDE con agente.)

En macOS (usa Homebrew; si no lo tienes, instálalo primero con el comando de su página):

brew install --cask r quarto
brew install git

En Windows (PowerShell; winget viene incluido en Windows 10/11):

winget install -e --id RProject.R
winget install -e --id Posit.Quarto
winget install -e --id Git.Git
Nota

Plan B sin terminal (o si el wifi de la sala no coopera): los instaladores gráficos de R, Quarto y Git — ideal traerlos descargados de antes.

Advertencia

Después de instalar, cierra y reabre el IDE: las extensiones detectan R, Python y Git al arrancar.

2.4 4. Comunicación con GitHub (llave SSH)

Primero, la cuenta: créala en GitHub con tu correo institucional — así puedes pedir el Student Developer Pack, que entre otras cosas te da Copilot Pro gratis (después puedes agregar tu correo personal).

Con la cuenta creada, falta que tu computador pueda enviarle cambios (hacer push de tus commits) sin pedirte contraseña a cada rato. Para eso se usa una llave SSH: un par de archivos donde la llave privada nunca sale de tu máquina y la pública se registra en GitHub. Cuando ambas calzan, GitHub sabe que eres tú.

Los comandos van en la terminal integrada (macOS y Windows por igual, salvo donde se indica):

  1. Preséntate a Git — este nombre y correo quedan firmados en cada commit tuyo (usa el mismo correo de tu cuenta GitHub):

    git config --global user.name "Tu Nombre"
git config --global user.email "tu-correo@institucional.cl"

  2. Genera tu par de llaves (presiona Enter a todas las preguntas; dejar la passphrase vacía está bien para empezar):

    ssh-keygen -t ed25519 -C "tu-correo@institucional.cl"

  3. Copia la llave pública al portapapeles (la que termina en .pub; la privada no se comparte jamás):

    # macOS
pbcopy < ~/.ssh/id_ed25519.pub
    # Windows (PowerShell)
Get-Content ~\.ssh\id_ed25519.pub | clip

  4. Regístrala en GitHub: ve a github.com/settings/keys → New SSH key → ponle un título (“laptop-doctorado”) → pega la llave → Add SSH key.

  5. Prueba el saludo:

    ssh -T git@github.com

    La primera vez preguntará si confías en el servidor: responde yes. El éxito se ve así: Hi tu-usuario! You've successfully authenticated...

  6. Desde ahora, clona con la URL SSH (botón verde Code → SSH en cualquier repo):

    git clone git@github.com:aoliveram/Redes-Sociales-2026.git

  7. Tu primer ciclo completo — el ritmo que usarás todo el doctorado:

    git status                          # ¿qué cambió?
git add archivo_que_cambiaste.qmd   # preparar
git commit -m "Mi primer commit"    # guardar con mensaje
git push                            # enviar a GitHub

2.4.1 Tu primer script sobre el repositorio clonado

Ya tienes el curso completo en tu máquina. Lo que hiciste hasta ahora en la terminal fue interactivo: tú escribes, el intérprete responde. El trabajo real corre de otra forma: un script — un archivo con código que se ejecuta completo, de principio a fin. Esa es la unidad básica de un análisis reproducible: mismo archivo, mismos datos, mismo resultado.

El repositorio trae dos scripts gemelos (uno en R, otro en Python) que generan y comparan tres redes clásicas — aleatoria (Erdős–Rényi), mundo pequeño (Watts–Strogatz) y libre de escala (Barabási–Albert) — y guardan la tabla comparativa en outputs/. Desde la carpeta raíz del repositorio clonado:

Con R:

Rscript libro-redes-sociales-2026/scripts/compara_redes.R

Con Python (requiere pip install networkx la primera vez):

python3 libro-redes-sociales-2026/scripts/compara_redes.py

Ambos imprimen una tabla como esta y dejan un .csv en libro-redes-sociales-2026/outputs/:

red nodos aristas densidad transitividad dist_media grado_max
aleatoria 200 600 0.030 0.024 3.14 13
mundo_pequeno 200 600 0.030 0.445 4.50 8
libre_escala 200 594 0.030 0.055 2.94 33

Misma cantidad de nodos y aristas, tres mundos distintos: el mundo pequeño concentra transitividad (tus amigos son amigos entre sí), la libre de escala produce hubs (un nodo con grado 33 donde la aleatoria llega a 13) y las distancias más cortas. Abre los scripts en el editor y míralos: son ~30 líneas cada uno, y es exactamente el tipo de código que escribirás en la semana 1. Cuando los hayas corrido, pídele a tu agente que te explique el script línea por línea — es tu primera conversación con él sobre código real.

2.4.2 Tu primera contribución al repositorio

Cada estudiante tiene una carpeta personal dentro de Proyectos-Estudiantes/: Amanda/, Camila/, Felipe/, Abraham/ y Carlos/. Todo lo que produzcas en el curso vive ahí, y la razón es práctica: si los cinco hacen commit del mismo archivo en la misma ruta, git genera conflictos que hay que resolver a mano; si cada uno escribe solo en su carpeta, los cinco pushes conviven sin pelearse.

El resultado de tu primera conversación con el agente se sube ahí. Pídele (reemplazando TU-NOMBRE por el nombre de tu carpeta):

Corre el script libro-redes-sociales-2026/scripts/compara_redes.R y escribe un reporte breve en Markdown en Proyectos-Estudiantes/TU-NOMBRE/01_comparacion_redes.md que incluya: qué hace el script, qué distingue a cada una de las tres redes, y una pregunta que te haya quedado dando vueltas. Después haz commit y push con un mensaje descriptivo.

Cuando los cinco reportes estén arriba, el historial del repositorio mostrará la primera foto del curso completo trabajando — cinco commits, cinco carpetas, cero conflictos.

Nota

Para poder hacer push necesitas ser colaborador del repositorio: te llegará una invitación de GitHub por correo — acéptala antes de este paso. Si el push falla igual, avísame.

2.4.3 Los cinco comandos de git que usarás a diario

Comando Para qué sirve
git status Muestra qué cambió desde el último commit. Tu brújula: úsalo antes que todo lo demás.
git add <archivo> Marca ese cambio para el próximo commit (git add . marca todos).
git commit -m "mensaje" Guarda la fotografía de lo marcado, con un mensaje que dice qué y por qué.
git push Envía tus commits al repositorio en GitHub.
git pull Trae desde GitHub los commits nuevos de los demás. Siempre antes de ponerte a trabajar.

Ese es el ciclo completo: pull al empezar, status → add → commit → push al terminar. Todo lo demás de git es refinamiento.

3 Reglas del juego

Ejercicio de apertura. Pídele a tu agente: “¿puedo concluir que el actor más central es el más influyente del grupo?”. La respuesta correcta es no (centralidad ≠ influencia causal; lo veremos en la semana 3). ¿Tu agente te frenó o te dio la razón? Compara con el resto del curso: esa diferencia — aceptar la salida o examinarla — es exactamente el tema de este bloque.

3.0.1 La idea que ordena todo: propiedad epistémica

Este curso adopta el marco del profesor Fábrega sobre propiedad epistémica (epistemic ownership, Fábrega, en revisión): usar GenAI está bien —es parte de cómo se investiga hoy— pero el producto final es tuyo solo si mantienes el mando justificatorio sobre él: la capacidad de reconstruir sus razones, integrarlas a tu argumento y defenderlas ante preguntas. La falla característica no es usar IA, sino la desposesión justificatoria: quedarte con un producto correcto cuyas razones no puedes reconstruir.

De ahí salen las cuatro prácticas del curso:

  1. Declaración de uso. Cada entrega incluye una nota breve: qué asistente usaste, para qué tareas y qué verificaste tú.
  2. Critica la salida. Antes de aceptar código o interpretación de la IA, escribe una razón por la que podría estar mal (¿datos?, ¿supuestos?, ¿paquete inventado?).
  3. Primero a mano, después con IA. Los conceptos nuevos de cada semana se practican primero sin asistente; la IA entra para acelerar lo que ya entiendes. (La evidencia muestra que la propiedad se sostiene mejor cuando tu intento propio precede a la asistencia.)
  4. La interpretación es tuya. La IA puede redactar código; la lectura sustantiva de los resultados —qué significa ese coeficiente en tu red— no se delega.

3.0.2 Cómo se evalúa: entrega + defensa

El ciclo semanal tiene dos tiempos:

  1. La entrega. Desarrollas la actividad fijada y la envías (notebook reproducible + PDF). Se espera y se alienta que uses IA: no está penalizado, y preferimos que aprendas a usarla bien antes que simular que no existe. Declara su uso como indica la regla 1.
  2. La defensa. Después de recibir las entregas, las reviso y preparo un set de preguntas personalizado para cada uno, sobre su propio trabajo: “tú escribiste esto; defiende esta decisión”. Por qué ese modelo nulo y no otro, qué habría pasado con otra métrica, qué significa ese coeficiente aquí. La defensa es individual y es donde demuestras que el razonamiento es tuyo, hayas usado IA o no.

En términos del marco anterior: la entrega mide la calidad del producto; la defensa mide tu capacidad de responder por él. Las dos cosas juntas son la nota.

3.0.3 Preguntas relámpago por sorteo (15–20% de la nota final)

Durante las sesiones haremos preguntas conceptuales breves, asignadas con un generador de números aleatorios. Esto sí lleva nota — el porcentaje exacto (15% o 20%) quedará fijado en el syllabus actualizado. Las reglas:

  • Equidad garantizada por diseño. Cada ronda es aleatoria, pero el sorteo es sin reposición: nadie repite hasta que los cinco hayan respondido. Al final del curso, todos habrán respondido exactamente la misma cantidad de preguntas (fijamos el total de preguntas por sesión como múltiplo de 5).
  • Conceptuales, no de memoria. “¿Qué te diría este resultado?”, no “¿cuál es la fórmula de X?”. Se evalúa el razonamiento, no la recitación: una respuesta equivocada bien argumentada vale más que una correcta sin argumento.
  • Transparencia. La semilla del generador se anuncia al inicio de cada sesión, así el sorteo es verificablemente aleatorio y reproducible por cualquiera.
  • Si alguien falta, sus preguntas se difieren a la sesión siguiente (no se re-sortean), para mantener las cuotas iguales.

El mecanismo exacto, en el R que ya tienes instalado:

sortear_preguntas <- function(nombres, n_preguntas, semilla) {
  stopifnot(n_preguntas %% length(nombres) == 0)  # cuotas iguales garantizadas
  set.seed(semilla)                               # semilla anunciada al inicio
  rondas <- n_preguntas / length(nombres)
  unlist(lapply(seq_len(rondas), function(r) sample(nombres)))
}

curso <- c("Amanda", "Camila", "Felipe", "Abraham", "Carlos")
sortear_preguntas(curso, n_preguntas = 10, semilla = 20260803)
# dentro de cada ronda de 5, orden aleatorio; entre rondas, re-sorteo

3.0.4 La evidencia detrás de estas reglas

Lecturas que fundamentan este diseño (todas verificadas, 2024–2026):

  • Bastani et al. (2025), PNAS — experimento de campo con ~1.000 estudiantes: el acceso a GPT mejora la práctica pero empeora el examen sin IA… salvo cuando el tutor tiene guardrails pedagógicos, que eliminan el daño.
  • Kestin et al. (2025), Scientific Reports — RCT en Harvard: un tutor IA diseñado con andamiaje experto superó a la clase activa presencial. El diseño importa más que la herramienta.
  • Lee et al. (2025), CHI — 319 trabajadores del conocimiento: a mayor confianza ciega en la IA, menos pensamiento crítico; a mayor confianza en el dominio propio, más.
  • Fan et al. (2025), BJET — “pereza metacognitiva”: con ChatGPT mejora la tarea inmediata, pero no la transferencia de conocimiento.
  • Prather et al. (2024), ICER — en programadores novatos la IA amplía la brecha: ayuda a quienes ya tienen estrategias metacognitivas y crea ilusión de competencia en quienes no.
  • Fábrega (en revisión), Epistemic Ownership in Human-AI Cognition — el marco conceptual del curso: propiedad epistémica, la firma cognitiva y la desposesión justificatoria.

4 Diccionario mínimo

Los términos que usaremos todo el curso, en una línea cada uno:

  • Terminal — la ventana de texto donde escribes comandos y el sistema responde. La del IDE es la misma del sistema, embebida en la ventana del editor.
  • CLI (command-line interface) — un programa que se opera escribiendo comandos en la terminal: git, quarto, Rscript, ssh… y también claude. Sin ventanas ni botones.
  • IDE (integrated development environment) — la aplicación gráfica que integra editor de código, explorador de archivos, terminal y extensiones: VS Code, Antigravity, RStudio.
  • Extensión — módulo que agrega capacidades al IDE: soporte de R, render de Quarto, un agente de IA. Se identifica con su nombre único editor.nombre.
  • Script — archivo con código que se ejecuta completo, de principio a fin (compara_redes.R). La unidad básica del análisis reproducible.
  • Git — el programa (una CLI) de control de versiones: registra la historia de cambios de una carpeta, commit a commit.
  • Repositorio (repo) — una carpeta cuya historia rastrea Git: el proyecto completo con su memoria incorporada.
  • Commit — una fotografía del repositorio en un instante, acompañada de un mensaje que explica qué cambió y por qué.
  • Push / pull — enviar tus commits al repositorio remoto / traer a tu máquina los commits nuevos.
  • Clonar — copiar un repositorio remoto a tu máquina, con toda su historia incluida.
  • GitHub — el servicio web donde viven las copias remotas de los repositorios: respaldo, colaboración y portafolio público de tu trabajo.
  • SSH / llave SSH — canal cifrado y par de llaves (privada en tu máquina, pública en GitHub) con que tu computador se identifica sin contraseñas.
  • GitHub Pages — el hosting gratuito de GitHub que convierte una carpeta del repo en un sitio web. Este libro que estás leyendo es un GitHub Pages.
  • Markdown (.md) — texto plano con marcas simples (#, **, -) que se convierte en documento formateado. El formato de los reportes que genera el agente.
  • Quarto (.qmd) — Markdown más bloques de código ejecutable: al renderizar, corre el código e inserta los resultados en el documento (HTML o PDF). El formato de tus entregas.
